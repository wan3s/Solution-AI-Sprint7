# Автоматическое выявление подозрительных операций по счетам

## Готовность данных

| Поле | Значение |
| --- | --- | 
| Источник правильного ответа | В постановке задачи говорится, что размеченных данных нет. Поэтому либо накапливать базу, либо разметить руками имеющийся набор данных | 
| Качество | Могут встречаться неправильно определенные операции. Для этого можно размечать данные несколькими экспертами и выбирать ответ, который проставило большинство |
| Объём по важному классу | В задании явно не указано, как посчитать по имеющейся информации - не понимаю |
| Разметка | Разметки нет |
| Cмещение отбора | Есть небольшой количество углубленно рассмотренных операций (4%, 400 в месяц). Однако большинство заканчивается ничем | 
| Репрезентативность | Неизвестно |
| Право использовать | Есть потенциально чувствительные данные, нужно уточнить у юристов |
| Владелец | Данные собирает финмон |
| Вердикт | Данные не готовы - нужно уточнить юридические моменты и разметить набор |

## Размещение 

Лучше выбрать on-premise, так как нам важна скорость, независимость от других сервисов (тем более внешних) и безопасность данных.

## Проверка

* Нужно по ровну примеров с отрицательным и положительным вердиктом, тк у модели точность может быть 0.99, но при этом кейсов в фродом - меньше 0.01. Тогда будет показывать высокую точность даже при неправильном определении реального фрода почти всегда. 
* Нужно, чтобы она точно определяла хотя бы 20000/35000 = ~57% операций. Остальные, если сомневается, отправляла на ручной разбор.
