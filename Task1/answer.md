# Постановка

## Автоматическое выявление подозрительных операций по счетам

| Поле | Что фиксируем? |
| --- | --- |
| Бизнес-действие | Снизится число операций, которые сотрудникам фин мона приходится рассматривать вручную |
| Объект и единица решения | Операция |
| Момент | Ответ нужен в реальном времени - пользователь совершает операцию и, если проверка пройдена, операция обрабатываться дальше практически в этот же момент |
| Операция | На ручной разбор попадает 35 тысяч операций в месяц. Сотрудники успевают обработать только 10 тысяч операций в месяц. То есть как минимум 25 тысяч операций в месяц нужно уметь обрабатывать автоматически |
| Модальность | Документ (какой-то request в сервис) |
| Выход модели | Вероятностная оценка фрода |
| Бизнес-выход | Ответ фрод / не фрод |
| Источник правильного ответа | Правильный ответ узнаем после проведения операции: если операцию заблокировали ложно, то по жалобе клиента в поддержку. Если операцию одобрили ложно, то по жалобе от регуляторов. Если жалоб не поступало, то скорее всего опеределили верно. |
| Конвейер | Звено, которое выдает вероятностную оценку - обучаемое. Далее детерменированный алгоритм сравнивает эту оценку с порогом. |
| Альтернативные постановки | Система может просто определять фрод / не фрод, а окончательное решение за человеком. |

## Распознавать и оцифровывать сканы документов, приложенных к кредитной заявке

| Поле | Что фиксируем? |
| --- | --- |
| Бизнес-действие | Процесс выдачи кредитов ускорится и снизится нагрузка на сотрудников банка |
| Объект и единица решения | Документ |
| Момент | Ответ может прийти с задержкой в несколько минут |
| Операция | Извлечение |
| Модальность | Документ |
| Выход модели | Извлеченный текст из документа |
| Бизнес-выход | Извлеченный текст из документа |
| Источник правильного ответа | Можно попросить клиента проверить корректность извлеченных данных и подтвердить / исправить |
| Конвейер | Загрузка файла -> Распознавание текста и извлечение -> Подставление полей в форму -> Подтверждение клиента, что все корректно |
| Альтернативные постановки | - |

## Маршрутизировать входящие обращения по нужным отделам

| Поле | Что фиксируем? |
| --- | --- |
| Бизнес-действие | Распределить нагрузку по специализированны отделам, снизить нагрузку на оператора, который маршрутизирует запросы |
| Объект и единица решения | Вопрос клиента |
| Момент | Возможна задержка до нескольких минут |
| Операция | Категория |
| Модальность | Текст |
| Выход модели | Kind отдела, куда нужно направить запрос |
| Бизнес-выход | Запрос направлен в нужный отдел |
| Источник правильного ответа | Оператор выбранного отдела может опеределить, туда ли пришел вопрос. Если нет, то перенаправить вручную в нужный отдел |
| Конвейер | Пользователь отправляет вопрос -> Классификатор определяет отедл -> Вопрос отправляется в нужных отдел |
| Альтернативные постановки | Просто перенаправить вопрос в нужный отдел и ответить не сразу в чате, а сказать пользователю, что ответ придет на почту |

# Обоснование выбора инициатив

## Автоматическое выявление подозрительных операций по счетам

| Поле | Значение |
| --- | --- |
| Ценность | Снизится число операций, которые сотрудникам фин мона приходится рассматривать вручную |
| Выполнимость | Задача вполне реальная, но есть риски |
| Данные | Используем исторические данные, которые вручную разметили сотрудники фин мона |
| Риск | Будет низкий recall и будем ложно пропускать много схемных платежей |

## Распознавать и оцифровывать сканы документов, приложенных к кредитной заявке

| Поле | Значение |
| --- | --- |
| Ценность | Процесс выдачи кредитов ускорится и снизится нагрузка на сотрудников банка |
| Выполнимость | Типовая OCR задача |
| Данные | Можно использовать обученную модель, которая распознает текст |
| Риск | Утечка чувствительных данных наружу |

## Маршрутизировать входящие обращения по нужным отделам

| Поле | Значение |
| --- | --- |
| Ценность | Распределится нагрузка по специализированны отделам, снизится нагрузка на оператора, который маршрутизирует запросы |
| Выполнимость | Простая задача в области NLP |
| Данные | Можно использовать исторические данные (куда оператор перенаправлял вопрос). Правда отделы не все разом появились, какие-то раньше, какие-то позже. Нужно учесть при обучении моедли |
| Риск | Направили вопрос не в тот отдел. В таком случае коллеги вручную переадресуют вопрос |
